# SoS-DSL Demo Harness

This directory contains a hand-written `MonoBehaviour` that drives the
**generated** `DeliverySlaContract` through the three demo scenarios.
It is **not** regenerated by `cadl codegen`; edit it freely.

## Setup

1. In a new or existing Unity scene, create an empty GameObject named
   `DeliveryContractRuntime`.
2. Attach `DeliveryContractDemo` (this folder) as a component.
3. Set the `Scenario` field in the Inspector:

   - `Happy`   — assign + ack within 5s → `Accepted`.
   - `Late`    — assign + no ack       → `Violated` via deadline.
   - `Battery` — assign + battery drop → `Violated` via monitor.

4. Press Play. The `Console` window will show one entry per
   lifecycle / violation event, e.g.

   ```
   [lifecycle DELIVERY_SLA/req-001 Proposed -> Assigned (assign, event) @ 100ms]
   [violation DELIVERY_SLA/req-001 accept Major deadline:accept @ 5100ms]
   [lifecycle DELIVERY_SLA/req-001 Assigned -> Violated (<jump>, deadline) @ 5100ms]
   ```

## Wiring to the rest of the simulator

Two helpers are provided so you can feed the **real** simulator into
the contract runtime without editing any of the existing scripts:

### `ContractRuntimeHost.cs` (singleton)

Drop one empty GameObject named `ContractRuntimeHost` into the scene
root and attach this component. It owns the single `ContractRuntime`
that all bridges share, ticks it every Update, and echoes every
contract event to `UnityEngine.Debug.Log` (toggleable in the
Inspector).

### `PilotContractBridge.cs` (one per robot)

Attach this to each robot GameObject that already has a
`Pilot_CSoS` component. The bridge is **observation-only** — it does
not edit `Pilot_CSoS` — and translates state changes into contract
events:

| Pilot_CSoS state change | Contract event posted |
| --- | --- |
| `HasActiveDelivery` flips false → true | `DISPATCHER -> ROBOT[i] : route_assignment` followed by `ROBOT[i] -> DISPATCHER : ack(accepted)` |
| First Update while delivering | `ROBOT[i].status == InTransit` |
| `DeliveryCount` increments | `ROBOT[i].status == Delivered`, then a fresh contract instance is opened |

Each robot gets its own contract instance, named
`robot-{id}-{deliveryNo}`.

The Inspector's `Robot Battery` slider feeds the world model used
by `battery_guard` (and other monitors that read `ROBOT.battery`);
swap this for a real telemetry feed when you have one.

### Bridge in plain `DeliveryContractDemo` mode

The original `DeliveryContractDemo` component still works for the
three scripted scenarios (Happy / Late / Battery) without any
arbitrator running — useful for unit-style smoke tests of the
generated state machine.

## Regeneration

The `Generated/` and `Runtime/` siblings of this folder are emitted
by:

```bash
cd cadl_repo
cadl codegen examples/sos_dsl_robot_delivery.cadl \
    --target unity-csharp \
    --output ../cadl-raspimouse-simulator/unity/Assets/Scripts/SoSDsl
```

Re-run after any change to `lifecycle:` / `monitors:` blocks in the
CADL source. **Do not edit `Generated/` or `Runtime/` by hand** — the
next regeneration will overwrite your changes.
